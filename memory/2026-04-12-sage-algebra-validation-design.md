# Sage Algebra Validation Design

Validate Wile's algebra libraries against SageMath as an independent oracle.

## Problem

Wile's `(wile algebra)` library implements algebraic structures (rings, fields,
lattices, semirings, Boolean/Heyting algebras) and a term rewriting system with
equational axioms. The existing `validate-*` functions spot-check algebraic laws
on hand-picked samples. Two gaps remain:

1. **Value correctness** — laws can hold even when operations compute wrong
   values consistently. No external oracle checks that `ring-plus` on the
   integer ring actually computes addition.

2. **Rewriting soundness** — each axiom-driven rewrite step should preserve
   semantic equivalence. No test evaluates both the original and rewritten
   terms in a known-correct algebra to verify this.

SageMath provides trusted implementations of every algebraic structure Wile
implements, making it the right oracle for both gaps.

## Architecture

```
tools/sage/verify_algebra.sage        — live harness (both phases)
tools/sage/README.md                  — invocation, Sage version, seed docs
test/wile/sage-generated/             — static .scm snapshots for CI
```

Invocation:

```bash
sage tools/sage/verify_algebra.sage                    # live run, both phases
sage tools/sage/verify_algebra.sage --phase structures # phase 1 only
sage tools/sage/verify_algebra.sage --phase rewriting  # phase 2 only
sage tools/sage/verify_algebra.sage --snapshot         # write .scm files
sage tools/sage/verify_algebra.sage --seed 123         # custom RNG seed
```

## Phase 1: Structure Validation

Generate (input, expected-output) test vectors for each algebraic structure.
Sage computes the expected values; Wile must match.

### Structures and Sage Oracles

| Wile Structure | Sage Oracle | Operations Tested |
|---|---|---|
| `integer-ring` | `ZZ` | `+`, `*`, `-`, negate, zero, one |
| `rational-field` | `QQ` | `+`, `*`, `-`, `/`, negate, reciprocal |
| `modular-ring N` | `Zmod(N)` | `+`, `*`, `-`, negate |
| `powerset-lattice` | `Posets.BooleanLattice(n)` | join, meet, leq, bottom, top |
| `powerset-boolean` | `BooleanLattice(n)` + complement | join, meet, complement |
| `flat-lattice` | Custom `FinitePoset` | join, meet, leq |
| `boolean-semiring` | Manual (`or`/`and`) | plus=or, times=and |
| `tropical-semiring` | `TropicalSemiring()` | plus=min, times=+ |
| `counting-semiring` | `ZZ` (as semiring) | plus=+, times=* |

### Coverage Extension (June 2026)

Six additional structures were added by the oracle coverage extension
(`plans/2026-06-07-sage-oracle-coverage-design.md`). Each generates a snapshot in
`test/wile/sage-generated/` with an `;;; Oracle source:` header line indicating
how expected values were computed:

- `polynomial` — `Sage-builtin`: Sage `PolynomialRing(ZZ/QQ)` for negate, derivative, degree, leading-coeff, eval, plus, minus, times, gcd.
- `graph` — `Sage-builtin`: Sage graph invariants for spanning-tree count and chromatic polynomial across seven preset graphs.
- `semiring-matrix` — `hybrid`: counting-semiring ops via Sage `Matrix(ZZ)`; tropical permanent and boolean closure via in-harness Python reference.
- `group` — `hybrid`: cyclic group ops via Sage `Zmod(n)`; Burnside necklace counts via `euler_phi` + orbit formula.
- `heyting` — `Python-reference`: powerset Heyting algebra (join/meet/implies/negate/leq?) against an in-harness Python reference that replicates Wile's operand-traversal order (not universe order; see Task 7 correction in the plan).
- `interval` — `Python-reference`: interval arithmetic (add/sub/mul with inf-aware endpoints) against an in-harness Python reference mirroring Wile's infinity conventions.

### Test Vector Generation

- Numeric (ring, field, modular): all pairs from sample range (e.g., -10..10)
- Powerset: all pairs of subsets for 3-4 element universe
- Flat lattice: all pairs including bottom/top sentinels
- Semirings: all pairs from their respective domains

## Phase 2: Rewriting Soundness

Claim under test: **for every rewrite step t -> t', evaluating t and t' in a
concrete algebra produces the same value.**

### Method

1. Generate random S-expression terms over a concrete algebra (depth 1-5,
   leaf values from small range)
2. Evaluate original term in Sage -> ground truth value
3. Normalize in Wile via `make-recursive-normalizer` with the algebra's
   theory projection (subprocess call)
4. Evaluate normalized term in Sage -> post-rewrite value
5. Assert equality

Sage evaluates both sides. A bug in Wile's algebra operations cannot mask
a bug in Wile's normalizer — the oracle is independent of the system under test.

### Algebras and Axiom Coverage

| Algebra | Theory | Term Operators | Axioms Exercised |
|---|---|---|---|
| Integer ring | `ring->theory` | `+`, `*`, `neg` | identity, absorbing, commutativity, associativity, involution |
| Rational field | `field->theory` | `+`, `*`, `neg`, `recip` | + reciprocal involution |
| Boolean algebra | `boolean->theory` | `or`, `and`, `not` | + absorption, idempotence, complement involution |
| Powerset lattice | `lattice->theory` | `join`, `meet` | + absorption between two operators |

All seven axiom types covered:

| Axiom | Tested By |
|---|---|
| Identity | integer ring (+0, *1), lattice (join bot, meet top) |
| Commutativity | integer ring (+), lattice (join, meet) |
| Absorbing | integer ring (*0) |
| Idempotence | lattice (join, meet), boolean (or, and) |
| Involution | integer ring (neg), field (recip), boolean (not) |
| Absorption | lattice (join/meet), boolean |
| Associativity | integer ring (+, *), lattice (join, meet) |

### Term Generation

Recursive with depth bound:

```
term ::= leaf
       | (op term term)      -- binary: +, *, or, and, join, meet
       | (unary-op term)     -- unary: neg, recip, not
```

Leaf values from a small range per algebra. Depth 1-5. 1000 terms per algebra
for live runs, 50-100 curated for snapshots.

### Edge Cases to Target

- Identity elements as leaves (0, 1, bottom, top)
- Nested involutions (neg(neg(neg(x))))
- Absorption patterns (join(a, meet(a, b)))
- Mixed operators ((+ (* 0 x) (+ y 0)))
- Already-normal terms

### Wile Subprocess Interface

```python
def wile_normalize(term_sexp, algebra_setup):
    scheme = f"""
    (import (wile algebra) (wile algebra symbolic) (wile algebra rewrite))
    {algebra_setup}
    (let-values (((result trace) (norm '{term_sexp})))
      (write result))
    """
    result = subprocess.run(['wile', '-e', scheme],
                            capture_output=True, text=True)
    return result.stdout.strip()
```

### Snapshot Format

Rewriting snapshots test the composed pipeline:

```scheme
;; Original: (+ (* 0 5) (+ 3 0))  evaluates to 3 in ZZ
;; Normalized: 3
(let-values (((result trace) (norm '(+ (* 0 5) (+ 3 0)))))
  (test 3 result))
```

## Phase 3: Confluence (Future)

Not in scope for initial implementation. Design notes to avoid blocking it:

Given a term t and theory {A1..An}, does every axiom ordering reach the same
normal form? Test by normalizing under `theory-prioritize` with permutations
of axiom names. Expensive (n!) but tractable for small theories and terms.

Existing primitives (`theory-prioritize`, `make-recursive-normalizer`,
`discover-equivalences`) support this directly. No new Wile code needed.

Sage serves as tiebreaker when normal forms differ — "which is correct?"

Nothing in Phases 1-2 prevents Phase 3.

## CI Integration

Snapshot files in `test/wile/sage-generated/` run as part of `make test`.
No Sage dependency in CI. Regeneration is a deliberate act:

```bash
sage tools/sage/verify_algebra.sage --snapshot
# inspect diff
git add test/wile/sage-generated/
```

Header comments in generated files record Sage version, date, and seed
for reproducibility.
