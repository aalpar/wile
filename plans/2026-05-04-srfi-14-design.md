# SRFI-14 Character Sets — Design

**Status**: Approved (2026-05-04). Five clarifying decisions answered; ready for the companion implementation plan (`2026-05-04-srfi-14-impl.md`, to be drafted via `writing-plans`).

**Goal**: Add the [SRFI-14 Character-Set Library](https://srfi.schemers.org/srfi-14/) to Wile's default library set as `(srfi 14)`, plus one Wile-specific iteration helper exposed via `(wile charsets)`.

**Implementation policy**: Hybrid Go + Scheme. Wile gains a new `char-set` value type (Go-side primitive) and 18 FFI primitives in a new `extensions/charsets/` package (17 SRFI-14 + 1 internal `%make-named-charset` helper). The remaining 23 procedures are pure Scheme on top of those primitives, plus 17 named-set constants built from Go's `unicode` tables. Total user-visible surface: **57 names from SRFI-14** (out of 64 in the spec; 7 deferred per §11) plus **1 Wile-specific name** (`char-set-ranges` in `(wile charsets)`).

This is a deliberate departure from SRFI-13's "all Scheme v1" rule because SRFI-14 introduces a brand-new value type (not just procedures over existing types), and forcing record-type emulation when the natural fit is a primitive type would itself be the inconsistency. See §1 Q3 for full rationale.

## 1. Decisions matrix

| # | Question | Choice | Rationale |
|---|---|---|---|
| Q1 | Internal representation? | **Inversion list** (sorted vector of `(lo . hi)` ranges) | Matches Chibi/Larceny; scales to full Unicode without bitmap memory blowup; ranges align with Go's `unicode.RangeTable` shape. |
| Q2 | Mutability semantics? | **Fully immutable**; `!`-suffix forms always allocate fresh | Spec explicitly permits this. Inversion-list set algebra naturally allocates new range slices anyway, so the "linear update" win is illusory on this representation. Aligns with Wile's other value-typed primitives. |
| Q3 | Pure Scheme vs. Go FFI? | **FFI for value type + bulk ops; Scheme for the rest** | A new value type wants to be a primitive (single type-tag check vs. record-type-descriptor lookup). Named char-sets need Go's Unicode tables anyway. FFI surface is small (~18 primitives) and stable. |
| Q4 | Unicode reach for named char-sets? | **Full Unicode via Go's `unicode` package** | Wile is already Unicode end-to-end (`char-alphabetic?` calls `unicode.IsLetter`). Latin-1-only `char-set:letter` would create an inconsistency where the same character tests `#t` under `char-alphabetic?` and `#f` under `char-set-contains? char-set:letter` — a bug, not a tradeoff. |
| Q5 | Cut-list scope? | **Cut 7 names**: `char-set-hash`, cursor protocol (4 names), `char-set-diff+intersection` and `!` | Each cut has spec-language cover ("implementation-defined" / explicitly redundant / explicit micro-optimization). Each can be re-added later without breaking anyone. |

## 3. Architecture

Three new locations, one one-line edit to existing SRFI-13:

```
values/char_set.go                   ← CharSet Go type (lives with other value types)
extensions/charsets/charsets.go      ← FFI primitives package
extensions/charsets/properties_test.go ← Go property-style invariants
stdlib/lib/srfi/14.sld               ← Library manifest
stdlib/lib/srfi/14/predicates.scm    ← (Scheme layer files; see §5)
stdlib/lib/srfi/14/constructors.scm
stdlib/lib/srfi/14/iteration.scm
stdlib/lib/srfi/14/algebra.scm
stdlib/lib/srfi/14/named-sets.scm
stdlib/lib/srfi/14/util.scm          ← %char-set-walk-ranges helper
integration/testdata/srfi-14-tests-*.scm ← Six integration test files
internal/bootstrap/bootstrap.go      ← Register `charsets` extension
stdlib/lib/srfi/13/util.scm          ← TWO-LINE EDIT: add char-set? branch in %match-char?
stdlib/lib/srfi/13/{predicates,search,replace,trim-pad}.scm  ← Update deferral docstrings
stdlib/lib/srfi/13.sld               ← Add (import (srfi 14))
```

**Profile inclusion**: included in `Small` (R7RS-WG2 baseline), `Console`, and `KitchenSink`; excluded from `Tiny` (which stays minimal-core).

**Why `values/char_set.go` and not inside `extensions/charsets/`**: The `CharSet` value type must be visible to anything that handles `values.Value` generically (printer, equality dispatcher, type predicates). `extensions/charsets/` imports `values/`, not the other way around. This is the same pattern other primitive types follow.

**Why the package name `charsets` (not `strings`)**: SRFI-14 char-sets are conceptually independent of strings. Tying them to the strings extension would force string-related profiles to drag char-set support along, and create a circular conceptual dependency (SRFI-13 procedures take char-set arguments, but char-sets aren't *about* strings).

## 4. Value type

```go
// values/char_set.go
type CharSet struct {
    ranges []charSetRange  // sorted, disjoint, non-empty inversion list
}

type charSetRange struct {
    Lo, Hi rune  // inclusive endpoints; valid range satisfies Lo <= Hi
}
```

**Invariants** enforced by every constructor:

1. **Sorted** — `ranges[i].Lo > ranges[i-1].Hi` for all `i ≥ 1`
2. **Disjoint and non-adjacent** — `ranges[i].Lo > ranges[i-1].Hi + 1` (adjacent ranges merged)
3. **Non-empty per range** — `Lo <= Hi`
4. **Codepoint-valid** — `0 <= Lo` and `Hi <= 0x10FFFF`

These four invariants together give a unique canonical form for any logical char-set, so `char-set=` reduces to `slices.Equal` on the range slices. Set-algebra primitives are linear merges over sorted lists with no normalization step needed at the end.

`String()` rendering: `#<char-set: N ranges, M chars>` where N is `len(ranges)` and M is `char-set-size`. `Equal()` uses canonical-form comparison via `slices.Equal` on the range slices.

## 5. FFI primitive surface (18 primitives)

| Primitive | Arity | Notes |
|---|---|---|
| `char-set?` | 1 | Type-tag check |
| `char-set-contains?` | 2 | O(log n_ranges) binary search |
| `char-set-size` | 1 | O(n_ranges) sum of `Hi - Lo + 1` |
| `char-set=` | 1+ variadic | Vacuous case (1 arg) returns `#t` |
| `char-set<=` | 1+ variadic | Pairwise subset |
| `char-set-union` | 1+ variadic | Linear merge |
| `char-set-intersection` | 1+ variadic | Linear merge |
| `char-set-difference` | 1+ variadic | Linear merge (subtract rest from first) |
| `char-set-xor` | 1+ variadic | Linear merge |
| `char-set-complement` | 1 | Inversion against `[0, 0x10FFFF]` |
| `char-set` | 1+ variadic | Build from chars (sorted then run-length-collapsed) |
| `string->char-set` | 1 (+ optional base) | Optional base char-set to union into |
| `list->char-set` | 1 (+ optional base) | Same |
| `ucs-range->char-set` | 2 (+ optional `error?`, base) | Half-open `[lo, hi)`. `error?` defaults to `#t` (raise on out-of-range codepoints); any non-`#f` value is truthy per Scheme convention; only `#f` enables silent clipping to `[0, 0x10FFFF]`. |
| `char-set-copy` | 1 | Identity since immutable, but spec requires the name |
| `char-set->list` | 1 | Allocates char-list of size `char-set-size` |
| `char-set->string` | 1 | Allocates string of size `char-set-size` |
| `%make-named-charset` | 1 | Symbol-dispatched factory hitting Go's `unicode.RangeTable`. Internal — used by `named-sets.scm`. |

Plus one **`(wile charsets)` extra** (not in SRFI-14):

| Primitive | Arity | Notes |
|---|---|---|
| `char-set-ranges` | 1 | Returns list of `(lo . hi)` pairs. Gives Scheme code an efficient iteration handle so the rest of the library doesn't need codepoint-by-codepoint loops through FFI. |

All variadic primitives use `ParamCount: 1, IsVariadic: true` per the namespace migration convention (PR #544). `(char-set-union)` with zero args raises a Wile arity error — consistent with SRFI-14, which doesn't define a zero-arg case for these.

## 6. Scheme layer (23 procedures)

### A. Set-algebra `!` aliases (always allocate fresh)

```scheme
(define char-set-adjoin!        char-set-adjoin)
(define char-set-delete!        char-set-delete)
(define char-set-complement!    char-set-complement)
(define char-set-union!         char-set-union)
(define char-set-intersection!  char-set-intersection)
(define char-set-difference!    char-set-difference)
(define char-set-xor!           char-set-xor)
(define list->char-set!         list->char-set)
(define string->char-set!       string->char-set)
(define ucs-range->char-set!    ucs-range->char-set)
(define char-set-filter!        char-set-filter)
(define char-set-unfold!        char-set-unfold)
```

12 one-liners. The spec explicitly permits `!` forms to allocate fresh — exercised uniformly.

### B. Derived set algebra (built on union/difference + singleton)

```scheme
(define (char-set-adjoin cs . chars)
  (char-set-union cs (apply char-set chars)))

(define (char-set-delete cs . chars)
  (char-set-difference cs (apply char-set chars)))
```

### C. Iteration / query (built on `char-set-ranges`)

| Procedure | Implementation sketch |
|---|---|
| `char-set-fold proc init cs` | Walk ranges; for each range walk codepoints `lo..hi` accumulating |
| `char-set-for-each proc cs` | Same, discarding result |
| `char-set-map proc cs` | Same, collecting `(proc ch)` results into `list->char-set` |
| `char-set-filter pred cs [base]` | Walk ranges, keep codepoints matching `pred`, build via `list->char-set`. `base` is an optional char-set whose elements are unioned into the result. |
| `char-set-count pred cs` | Walk ranges, count codepoints matching `pred` |
| `char-set-every pred cs` | Walk ranges, short-circuit on first failure |
| `char-set-any pred cs` | Walk ranges, short-circuit on first success |

All seven share a `(let loop ((ranges (char-set-ranges cs))) ...)` skeleton. Factored into `%char-set-walk-ranges` in `14/util.scm` so the seven procedures are 3-5 lines each. **This is the single point where the inversion-list shape leaks into Scheme** — if the FFI representation ever changes, exactly one helper needs updating.

`char-set-unfold` (and `char-set-unfold!`) build via `list->char-set` per the spec's reference implementation; two forms (with and without seed-list).

`->char-set` is the dispatching constructor:

```scheme
(define (->char-set x)
  (cond ((char-set? x) x)
        ((string? x)   (string->char-set x))
        ((char? x)     (char-set x))
        (else (error "->char-set: not coercible to char-set" x))))
```

## 7. Named char-sets (17 constants)

```scheme
(define char-set:letter        (%make-named-charset 'letter))
(define char-set:lower-case    (%make-named-charset 'lower-case))
;; ... 12 more
(define char-set:empty         (char-set))
(define char-set:full          (ucs-range->char-set 0 #x110000))
(define char-set:ascii         (ucs-range->char-set 0 128))
```

`%make-named-charset` is a Go-side dispatch on a symbol that returns the corresponding `*unicode.RangeTable`-derived `CharSet`. Built once per name at first call, cached in a Go-level `map[string]*CharSet`. The mapping:

| Symbol | Source |
|---|---|
| `letter` | `unicode.L` |
| `lower-case` | `unicode.Ll` |
| `upper-case` | `unicode.Lu` |
| `title-case` | `unicode.Lt` |
| `digit` | `unicode.Nd` |
| `letter+digit` | union of `unicode.L` and `unicode.Nd` |
| `graphic` | `unicode.GraphicRanges` |
| `printing` | `unicode.PrintRanges` |
| `whitespace` | `unicode.White_Space` |
| `iso-control` | `unicode.Cc` |
| `punctuation` | `unicode.P` |
| `symbol` | `unicode.S` |
| `hex-digit` | hand-built `[(48 . 57) (65 . 70) (97 . 102)]` (ASCII-only per SRFI-14 spec) |
| `blank` | hand-built `[(9 . 9) (32 . 32)]` plus Unicode `Zs` category |

`char-set:empty`, `char-set:full`, `char-set:ascii` are direct constructions (no `%make-named-charset` call needed).

## 8. SRFI-13 unlock

Two-line edit to `stdlib/lib/srfi/13/util.scm`:

```scheme
;; Before:
(define (%match-char? criterion ch)
  (cond ((char? criterion)      (char=? criterion ch))
        ((procedure? criterion) (criterion ch))
        (else (error "string-* criterion must be char or procedure (char-set support deferred to SRFI-14)" criterion))))

;; After:
(define (%match-char? criterion ch)
  (cond ((char? criterion)      (char=? criterion ch))
        ((char-set? criterion)  (char-set-contains? criterion ch))
        ((procedure? criterion) (criterion ch))
        (else (error "string-* criterion must be char, char-set, or procedure" criterion))))
```

Plus docstring updates at four other deferral sites (`predicates.scm`, `search.scm`, `replace.scm`, `trim-pad.scm`) that mention "deferred to SRFI-14" — once SRFI-14 ships, those references become misleading and need to be rewritten as "supports char, char-set, or predicate criterion."

**Library dependency**: `13.sld` adds `(import (srfi 14))` (chosen over `cond-expand` based dispatch — explicit dependency follows R7RS conventions; SRFI-14 is foundational enough that "SRFI-13 without SRFI-14" isn't a use case worth defending).

## 9. Error contracts

No new sentinels. All FFI errors use `werr.WrapForeignErrorf` over existing globals:

| Site | Sentinel | Wrap message |
|---|---|---|
| Argument is not a `CharSet` (any FFI primitive expecting one) | `werr.ErrTypeMismatch` | `"char-set-XXX: argument N: expected char-set"` |
| `char-set-contains?` second arg not a char | `werr.ErrTypeMismatch` | `"char-set-contains?: argument 2: expected char"` |
| `ucs-range->char-set` `lo > hi` | `werr.ErrInvalidArgument` | `"ucs-range->char-set: lo (N) exceeds hi (N)"` |
| `ucs-range->char-set` codepoint out of range | `werr.ErrInvalidArgument` | `"ucs-range->char-set: codepoint N exceeds 0x10FFFF"` |
| `string->char-set` second optional arg is not a char-set | `werr.ErrTypeMismatch` | `"string->char-set: optional base argument: expected char-set"` |
| `%make-named-charset` unknown symbol | `werr.ErrInvalidArgument` | `"%make-named-charset: unknown named char-set: <symbol>"` (defensive) |

### Edge cases pinned down

1. `(char-set)` with no args → `char-set:empty`.
2. `char-set=` and `char-set<=` with one arg → both `#t` (vacuous).
3. `(char-set-union)`, `(char-set-intersection)` with no args → arity error per Wile's variadic convention. SRFI-14 doesn't define these.
4. Equality of char-sets with structural sharing → `eq?` may return `#t` for shared sets, `#f` for separately-built equal sets. Same as for strings.
5. `ucs-range->char-set lo lo` (zero-width range) → `char-set:empty`. SRFI-14 uses half-open `[lo, hi)` semantics.

## 10. Test strategy

Two layers plus three property-style invariants:

### Layer 1 — Go unit tests (`extensions/charsets/charsets_test.go`)

Table-driven, covering: inversion-list invariants for every constructor (with adjacency-merging exercised); set-algebra correctness on small canonical fixtures; variadic dispatch (1/2/5-arg cases); edge cases (empty, singleton, `0x10FFFF`); named-set caching (second call returns same `*CharSet` pointer); error wrapping (each site triggered, `errors.Is(err, sentinel)` matches, wrap message contains site identifier).

Target: **≥85% line coverage** for `extensions/charsets/` (verify exact `make covercheck` floor during phase 0).

### Layer 2 — Scheme integration tests (`integration/testdata/srfi-14-tests-*.scm`)

Six files run via existing `integration/r7rs_test.go` harness:

| File | Coverage |
|---|---|
| `srfi-14-tests-predicates.scm` | `char-set?`, `char-set=`, `char-set<=` — vacuous cases, variadic chains, equivalent-but-differently-built sets |
| `srfi-14-tests-constructors.scm` | All five constructors + `->char-set` + `char-set-copy` |
| `srfi-14-tests-iteration.scm` | `fold`, `for-each`, `map`, `count`, `every`, `any`, `unfold`, `unfold!`. Iteration order ascending. `every`/`any` short-circuit verified by side effect. |
| `srfi-14-tests-algebra.scm` | All set-algebra ops including `!`-aliases. Algebraic identities sampled on fixed sets. |
| `srfi-14-tests-named-sets.scm` | `(char-set-contains? char-set:letter #\a)` = `#t`; **consistency with built-in predicates** — every char in `char-set:letter` satisfies `char-alphabetic?`, every char in `char-set:digit` satisfies `char-numeric?` (sampled). `char-set:ascii` size = 128. |
| `srfi-14-tests-srfi-13-unlock.scm` | `(string-index "hello world" char-set:whitespace)` = `5`; `(string-trim "  hi  " char-set:whitespace)` = `"hi"`; `(string-tokenize "foo,bar;baz" (char-set #\, #\;))` = `("foo" "bar" "baz")`. Plus negative: criterion that's a number raises updated error message. |

### Layer 3 — Three Go property invariants (`extensions/charsets/properties_test.go`)

```go
// 1. Round-trip: list->char-set->list preserves the set (deduplicated, sorted).
//    Built on testing/quick with []rune of length 0..50.

// 2. Complement involution: complement(complement(cs)) == cs for arbitrary cs.

// 3. DeMorgan: complement(union(a, b)) == intersection(complement(a), complement(b))
//    for arbitrary a, b. Verified via char-set= (canonical form makes this exact).
```

Three tests, ~40 lines total. Probe set-algebra correctness across a much larger input space than fixtures could reach. Catch normalization bugs (any constructor producing non-canonical inversion lists fails one of these).

### Build discipline

Per CLAUDE.md "the build is not clean until `make lint && make covercheck` both pass." Each phase exit gate is both passing — no "fix lint warnings later." SRFI-13 PR established this precedent.

## 12. Phase plan (high-level)

Detailed per-phase breakdown ships in the companion `2026-05-04-srfi-14-impl.md` (drafted via `writing-plans` next). High-level shape:

**Phase 0 — Scaffolding & value type.** `values/char_set.go` (struct + invariants + `Value` interface); `extensions/charsets/charsets.go` skeleton + extension registration; profile inclusion; `stdlib/lib/srfi/14.sld` shell. **Exit gate**: `(import (srfi 14))` succeeds; `char-set?` bound and returns `#f` on everything.

**Phase 1 — Constructors + predicates + membership.** FFI: `char-set?`, `char-set-contains?`, `char-set-size`, `char-set-copy`, `char-set`, `list->char-set`, `string->char-set`, `ucs-range->char-set`, `char-set->list`, `char-set->string`, `char-set-ranges`. Scheme: `->char-set`. Tests: `srfi-14-tests-constructors.scm`, `srfi-14-tests-predicates.scm` (basic).

**Phase 2 — Set algebra.** FFI: `char-set=`, `char-set<=`, `char-set-union`, `char-set-intersection`, `char-set-difference`, `char-set-xor`, `char-set-complement`. Scheme: **10 `!`-aliases** (7 set-algebra: `char-set-adjoin!`, `char-set-delete!`, `char-set-complement!`, `char-set-union!`, `char-set-intersection!`, `char-set-difference!`, `char-set-xor!`; 3 constructor: `list->char-set!`, `string->char-set!`, `ucs-range->char-set!`) + `char-set-adjoin` + `char-set-delete`. The remaining 2 aliases (`char-set-filter!`, `char-set-unfold!`) defer to Phase 3 where their referents are defined. Three Go property tests. Tests: `srfi-14-tests-algebra.scm` + remainder of `srfi-14-tests-predicates.scm`.

**Phase 3 — Iteration / query layer.** Scheme: `char-set-fold`, `char-set-for-each`, `char-set-map`, `char-set-filter`, `char-set-filter!`, `char-set-count`, `char-set-every`, `char-set-any`, `char-set-unfold`, `char-set-unfold!`. `%char-set-walk-ranges` helper extraction. Tests: `srfi-14-tests-iteration.scm`.

**Phase 4 — Named char-sets.** FFI: `%make-named-charset`. Scheme: 17 `char-set:*` constants. Tests: `srfi-14-tests-named-sets.scm` including consistency-with-built-in-predicates check.

**Phase 5 — SRFI-13 unlock + cleanup.** Two-line edit to `%match-char?`. Update four deferral-message sites. Add `(import (srfi 14))` to `13.sld`. Tests: `srfi-14-tests-srfi-13-unlock.scm`. Update `CHANGELOG.md`, `TODO.md`, `BIBLIOGRAPHY.md`. Run SRFI-13 integration suite — zero regression required.

**Total scope**: ~1500-2000 lines across Go + Scheme + tests. **One PR.** No multi-PR split.

**Phase ordering rationale**: Each phase produces a working partial library on its own. The SRFI-13 unlock is *last*, so a mid-phase regression doesn't accidentally break SRFI-13 in the middle of the work — blast radius contained to SRFI-14.
